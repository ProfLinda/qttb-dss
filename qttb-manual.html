1. System overview

The QTTB Decision Support System (DSS) is a single-page web application that runs entirely in the browser. No installation is required. It integrates soil survey data, satellite vegetation indices, live daily weather, soil fertility analysis, and an irrigation water balance into one unified tool for agronomists operating across the four QTTB production areas in Albania.

2. Standard workflow — step by step

A complete survey cycle takes 15–20 minutes in the field and produces a saved record, a water balance assessment, and a farmer advisory ready to share.

  1. Open the DSS at https://proflinda.github.io/qttb-dss/ — works on any device with a browser, no login required.
  2. Survey → Step 1 Soil — click one of the four location buttons (Fushë Krujë / Korçë / Lushnje / Vlorë). GPS, soil type, horizon data, and land classification fill automatically from ASIG reference data.
  3. Enter or correct: commune name, surveyor, date, reference number, crop, and any field-specific soil data. Fill the 5-horizon auger table with texture, colour, and consistence observations.
  4. Click Next: Meteo → in the sub-bar to move to Step 2.
  5. Survey → Step 2 Meteo — click Connect Copernicus to auto-fill NDVI, EVI, NDWI from Sentinel-2, plus all 41 meteo fields from ERA5 climatology. Correct any field manually if needed.
  6. Click ✓ Save survey. The record saves locally and uploads to Supabase.
  7. Go to Water Balance — select location and crop, click Run water balance. The system fetches real daily weather from Open-Meteo and computes the full step-by-step soil water balance.
  8. Go to Farmer Advisory — enter the farmer's name and WhatsApp number, select language (English or Albanian), click Generate advisory. Share via WhatsApp, email, or print to PDF.
  9. All saved records are visible in the Records tab with filters by commune, area, and date range.
No internet? The ERA5 monthly climatology for all 4 zones is embedded in the form and works offline. The Open-Meteo live fetch and Copernicus NDVI require a connection. Saved records persist in the browser's local storage even without connectivity and sync to Supabase when connection is restored.

3. Soil & land survey tab

Location auto-fill

The four location buttons (📍 Fushë Krujë, 📍 Korçë, 📍 Lushnje, 📍 Vlorë) populate the following fields automatically from embedded ASIG reference data:

  • GPS coordinates (E and N)
  • Commune, district, QTTB area and crop
  • Slope %, slope class, landform, water table, irrigation, drainage, flooding, erosion
  • Land cover class, topsoil texture (h), subsoil texture (j), depth class, TAW class
  • Soil type description
  • All 5 horizon rows: texture code, colour (Munsell), TAW per horizon

After clicking a location button, edit any field that differs from the reference for the specific parcel being surveyed.

Horizon auger table

The table follows the LUPP2 / SRI Tirana proforma exactly. For each of up to 5 horizons enter: horizon code (Ap, B1, B2…), depth (cm), texture class, colour (moist Munsell), TAW (mm/cm), consistency, and stones. Subsoil texture sequences should be entered in order (e.g., sequence 5–6–1–5 enters as 5615).

Reference (Ref.133 example)

Click Example survey ↗ in the header to load the fully completed Ref.133 survey from Prezë, Fushë Krujë (2003). This shows how a complete record looks and can be used for training and calibration.

4. Meteo variables tab

Copernicus Sentinel-2 auto-fill

Click Connect Copernicus to fetch live vegetation indices from the Sentinel-2 L2A satellite for the GPS coordinates entered in Step 1. The system uses the Sentinel Hub Statistics API. Three indices are computed per pixel:

  • NDVI — Normalised Difference Vegetation Index: (B08 − B04) / (B08 + B04). Range −1 to +1. Values >0.5 indicate healthy green vegetation.
  • EVI — Enhanced Vegetation Index: 2.5 × (B08 − B04) / (B08 + 6×B04 − 7.5×B02 + 1). Less saturated than NDVI in dense canopies.
  • NDWI — Normalised Difference Water Index: (B03 − B08) / (B03 + B08). Positive values indicate water presence or high leaf water content.

A 10m × 10m polygon is drawn around the GPS point. Maximum cloud coverage is set to 60%. The most recent cloud-free scene within the last 30 days is used.

ERA5 monthly climatology (offline, embedded)

If Copernicus is unavailable, click Fill ERA5 estimates. The system fills all 41 meteo fields from a 30-year monthly average for the selected zone. The values are derived from ERA5-Land reanalysis and represent typical conditions for that month and location.

Fertilization recommendation engine

Select crop and expected yield. The engine computes N / P₂O₅ / K₂O in kg/ha adjusted for:

  • Yield-based nutrient removal (crop coefficients)
  • Soil organic matter level (reduces N requirement if OM > 2.5%)
  • Existing soil P and K (reduces application if adequate)
  • pH correction (increases P recommendation in alkaline soils)
  • Irrigation availability (reduces rates for dryland conditions)

An application schedule with split timings is provided for all 7 crops: apple, tomato, olive, wheat, maize, alfalfa, vines.

The fertilization recommendations are based on standard FAO crop nutrient coefficients. They should be validated against Gianluca's crop-specific thresholds once that document is received.

6. Water balance DSS tab

Methodology

The system implements a daily step-by-step soil water balance following FAO Irrigation and Drainage Paper 56. For each day:

SWC(t) = SWC(t-1) + Rain(t) - ETc(t)
ETc(t) = ETo(t) × Kc(month)
SWC clamped to: 0 ≤ SWC ≤ TAW
Irrigation alert when: SWC ≤ (TAW - RAW)

ETo source — Open-Meteo (live, no API key)

The system calls the Open-Meteo forecast API which includes ERA5-based reanalysis for the past 92 days. The ETo is provided directly as the FAO Penman-Monteith value — no manual calculation required. The API is free and supports CORS from any browser.

7. Farmer advisory tab

The advisory generator pulls data from all other tabs and formats it into a one-page report suitable for printing or sharing.

Language

Select English or Shqip (Albanian) from the language dropdown. All section headers, labels, and standard phrases translate. Content entered manually (observations, farmer name, commune) remains as entered.

Sections

Use the checkboxes to include or exclude any section: Soil profile · Irrigation alert · Fertilization · Disease risk · Meteo conditions · Observations. The irrigation alert appears as a large coloured banner at the top if the water balance has been run.

Sharing

  • WhatsApp — opens WhatsApp with a pre-formatted message. If a phone number is entered in the Contact field, opens a direct chat with that number. Message includes: farmer name, commune, crop, irrigation alert, and volume to apply.
  • Email — opens the default email client with subject and body pre-filled.
  • Print / PDF — opens a clean print window with only the advisory (no DSS navigation chrome). Use browser print to PDF.

8. Records tab

Filtering

Four filter inputs: commune (text search), QTTB area (dropdown), date from, date to. Filters apply instantly to local records. Click Load from database to apply the same filters server-side against Supabase and merge the results.

Record sources

Each record shows a badge: DB for records retrieved from the Supabase database, local for records saved only in browser storage. Records with the same reference number in both sources are deduplicated — the database version takes precedence.

Export

  • JSON — full record data including all horizons and meteo fields. Can be re-imported into another browser instance.
  • CSV — flat table of key fields for spreadsheet analysis.
  • HTML — printable form view matching the LUPP2/SRI proforma layout.

// Evalscript for NDVI + EVI + NDWI
//VERSION=3
function setup() {
  return { input:[{bands:["B02","B03","B04","B08","dataMask"]}],
           output:[{id:"ndvi",bands:1,sampleType:"FLOAT32"},
                   {id:"evi", bands:1,sampleType:"FLOAT32"},
                   {id:"ndwi",bands:1,sampleType:"FLOAT32"},
                   {id:"dataMask",bands:1,sampleType:"UINT8"}] };
}
function evaluatePixel(s) {
  const ndvi=(s.B08-s.B04)/(s.B08+s.B04+1e-4);
  const evi=2.5*(s.B08-s.B04)/(s.B08+6*s.B04-7.5*s.B02+1+1e-4);
  const ndwi=(s.B03-s.B08)/(s.B03+s.B08+1e-4);
  return {ndvi:[ndvi],evi:[evi],ndwi:[ndwi],dataMask:[s.dataMask]};
}

13. Client Q&A — responses to questions raised

Q: Can the system work offline in the field?
Partially. The soil survey form, ERA5 monthly climatology (all 41 meteo fields), and local ASIG reference data all work without internet. Saved records persist in browser storage. What requires connectivity: Copernicus NDVI fetch, Open-Meteo live water balance, and Supabase sync. The recommendation is to fill Steps 1 and 2 offline and sync when back in range.
Q: How do we get real daily weather data (ETo, rain) without the ERA5 Python script?
Open-Meteo is already connected and working. It provides the last 92 days of ERA5-based daily data (temperature, rainfall, FAO ETo pre-computed) plus a 7-day forecast — all free, no API key, no Python required. The Water Balance tab fetches it with one click. Data is automatically saved to the Supabase daily_climate table, so it accumulates over time with each use.
Q: Is the NDVI data from Sentinel-2 the same as what we see in the Copernicus Browser?
Yes. The system queries the same Sentinel-2 L2A archive via the Sentinel Hub Statistics API — the same data that powers the Copernicus Browser. The difference is that instead of viewing an image, the system computes a mean NDVI/EVI/NDWI value for the 10m × 10m area around the GPS coordinates and returns a number that can be saved in the survey record.
Q: Can multiple agronomists use the system simultaneously from different locations?
Yes. Each browser instance operates independently. Records save locally first, then sync to Supabase where they are visible to all users. The Records tab loads all Supabase records with a click. There is no conflict or locking — last write wins for the same reference number.
Q: How does the water balance handle actual vs estimated ETo?
Three sources are used in order of priority: (1) Open-Meteo live fetch provides FAO Penman-Monteith ETo computed by ECMWF from ERA5 — this is the most accurate option and requires only a browser connection. (2) ERA5 monthly climatology embedded in the form provides typical monthly ETo for each zone — used when offline or when the season predates the 92-day window. (3) Manual override — any ETo field can be edited directly. The system will use whichever source produced the value in the field at the time of the balance run.
Q: Can the farmer advisory be generated in Albanian?
Yes. Select Shqip from the language dropdown on the Farmer Advisory tab. All section headers, labels, and standard advisory phrases translate to Albanian. The irrigation alert, disease risk assessment, and fertilization section adapt accordingly. The farmer's name, commune, and observations remain as entered.
Q: What happens to data if the browser is closed or cleared?
Records saved before browser clearing are lost from local storage. However, any record that was synced to Supabase (visible with a DB badge in the Records tab) is permanently stored in the database and can be retrieved from any browser by clicking Load from database. The recommendation is to always Save survey, which triggers both local storage and Supabase upload simultaneously.
Q: What is the TAW value and how is it calculated?
TAW (Total Available Water, mm for 0–100cm profile) is computed from the soil texture of each horizon using the formula from FAO Irrigation Paper 56: TAW = Σ (FC − WP) × depth × aTAW_correction, where aTAW depends on soil consistence class. The system pre-computes TAW from the LUPP2 classification table (column 12) and populates it automatically when a location button is clicked. It can be overridden manually for specific parcels with known field measurements.
Q: Can we export all survey data for external analysis (Excel, GIS)?
Yes. The Records tab exports to: (1) CSV — flat table with all key soil and meteo fields, suitable for Excel or any GIS software that accepts tabular data; (2) JSON — complete structured data including all 5 horizons per record, suitable for import into other systems; (3) HTML — printable form matching the SRI proforma layout. The Supabase database can also be queried directly via the REST API using the anon key, or downloaded via the Supabase dashboard as a full CSV export.
Q: What ASIG layers are available and how current is the data?
Five layers are connected: Land use 2020 (perdorimi_tokes_2020), Pedology updated April 2024 (pedologjia_23042024), Agricultural suitability August 2019, Cadastral parcels April 2025 (parcela_kadastrale_qkd_042025 from ZRPP), and Orthophoto 2018. All layers are served live from the ASIG geoportal. The tiles render correctly in the map. Attribute data (clicking a parcel to get its classification) requires the asig-proxy deployment — see section 12.
Q: Is the Copernicus account shared or project-specific?
The Sentinel Hub credentials embedded in the system are project-specific. The CDS account (for ERA5 download) is separate and also project-specific. Both are currently free-tier accounts. If usage increases significantly — for example, running NDVI queries for hundreds of parcels per day — consider upgrading to a paid Sentinel Hub plan. The current free tier allows approximately 30,000 processing units per month, which is sufficient for several hundred parcel queries.
